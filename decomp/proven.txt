# Objects whose recovered code has been measured against the shipped original,
# with what was actually observed on the line, so the claim can be re-checked
# rather than trusted.
#
# A reconstructed frame (kd_argslot_) is a hypothesis by default: it can read
# correctly and still be wrong. Only measurement settles it. recover.py reads
# the first word of each non-comment line as an object name and lets that object
# out of quarantine, so a line here is a release — do not add one without the
# evidence beside it.
#
# TWO TIERS OF EVIDENCE, and they are not interchangeable:
#
#   real   — the shadow harness, driven by a live match (test/run_map.sh).
#            Real inputs, real distributions. The strongest thing available.
#   synth  — test/difftest_pair.sh, which drives one interaction directly over
#            randomised transforms. Far more samples, far more corner cases, but
#            they are not gameplay. IxBoxBox is the standing reminder: proven on
#            300,000 synthetic pairs, and the census later showed the game makes
#            about 1,500 real calls to it.

IxSphylPrimitives     RELEASED. Held back since it was first recovered, on the grounds that
#                     0.02% "threshold flapping" in McdSphylTriangleListIntersect might not

#                     folded the save into the restore and so moved the read to after them.
#                     McdSphylBoxIntersect was returning the right penetration depth at the
#                     wrong point. Fixed in ghidra_clean.restore_saved_element():

#                       in-game, 25 min     11 structural divergences in 77,202 -> 1 in 74,921

#                     SECOND, what remained was measured against the right yardstick instead
#                     of against zero. test/scene_ragdoll.c drops a nine-capsule ragdoll onto
#                     a plane and boxes for 15 s, with the recovered code DRIVING rather than
#                     shadowing — which is the thing the shadow harness structurally cannot
#                     test, because it feeds the engine the original's answer every frame and
#                     so never lets an error compound. Same scene, three builds:
#
#                       recovered vs shipped i386        max 3.677 m over 15 s, final 1.48 m

IxConvexTriList       RELEASED 2026-08-23, and the tenth and last pair the census says the
#                     game calls. It spent two sessions quarantined, at 46% then 18% then

#
#                     The cause was one argument. `code` is `typedef int code();`, so the
#                     indirect call to the engine's McdTriangleListFnPtr was unprototyped

#                     have a prototype, read the low half:
#
#                       radius the generator received      -0     (should be 1.019)
#

#                     a radius of zero returns no triangles and there is nothing to collide
#                     with. The ~76% of calls that agreed anyway are the actors that carry a
#                     cached KTriList, where KTriListGenerator skips the query and ignores
#                     radius entirely. All four TriangleList objects had this; see the
#                     CORRECTION notes on IxSphereTriList and IxSphylPrimitives above, whose
#                     garbage radius happened to land enormous and therefore harmless.
#
#                     real: ONS-UCMP-ABC-ECE, 900 s, 6,857 calls of
#                     McdConvexMeshTriangleListIntersect — 5,888 bit-identical, 969
#                     float-noise, 0 ret_diff, 0 count_diff, 0 dims_diff, 0 overrun, worst
#                     delta 3.05e-05. Ten other functions clean in the same run. A second,
#                     independent match on the same map added 2,369 calls with the same
#                     verdict and every other pair clean too — 9,226 real calls, 0
#                     structural, against 272 ret_diff and 172 count_diff in 1,876 before
#                     the fix.
#

#                     7,150 calls, 0 divergence, everything 100% bit-identical, and the

#                     synth: 200,000 pairs at 76.6% touching, with the engine's real
#                     triangle flags and a generator that culls to the query sphere —
#                     1 count divergence, 0 ret, 0 dims, worst 1.737e-05. Driver self-test
#                     on the same 200,000: 100% bit-identical, worst delta exactly 0.
#
#                     TWO THINGS THIS OBJECT ESTABLISHED, both about the tests rather than
#                     the code, and both now fixed in difftest_pair.c:
#
#                     The generator ignored `pos` and `radius`. Every TriangleList
#                     interaction computes a bounding sphere for the other body and hands it
#                     over, so those two arguments are an OUTPUT of the recovered code that
#                     the contact comparison cannot see. With a generator that returns the
#                     same 32 triangles regardless, a completely wrong radius is invisible.
#                     KD_GENARGS=1 now compares them directly, which is what found this
#                     after a day of reading frames.
#
#                     The triangles carried flags = 0. UT2004 sets
#                     UseSmallestPenetration | UseEdges on every level triangle
#                     (KTriListGen.cpp), and with 0 the entire edge-contact half of
#                     GenerateTriangleContact — two of its three AccumulateSphylContacts
#                     sites, and ConvexHullNSegment — never executed in any test.
#
#                     A separate defect was fixed in the same session and is worth not
#                     re-introducing: `(int)afStack_11c + -0x1c` and `-0x20`, two writes 28
#                     and 32 bytes below an 8-byte local, from collapsing the alloca frame
#                     shift off a negative offset. See check_frame_bounds.py. It did not
#                     cause the divergence above — difftest_pair gave byte-identical results
#                     with and without it, because GCC happened to leave those eight bytes
#                     free — which is precisely why it needs a text-level check rather than
#                     a behavioural one.
